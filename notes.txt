1. Array:
	•   Memory Inefficiency: Middle insertions or deletions often require shifting elements, leading to memory overhead.
	•	Memory Waste while deletion : Replacing elements with null does not reduce the array size, causing potential memory inefficiency.
	•	Null Pointer Exceptions: Improper handling of null values may lead to runtime errors if we make the values as null.
	•	Fixed Size Limitation: Arrays have a fixed size, making dynamic insertions/deletions challenging compared to data structures like linked lists.
	•	Performance Impact: Frequent insertions/deletions in the middle of large arrays may significantly impact performance due to shifting elements.
    •   Initializing an array static means allocating memory and setting initial values for each element optionally.
    • It is generally recommended to put square brackets before the variable name for clarity and consistency while defining array
    • Arrays.fill() method is used to fill the arrays dynamically or fill at specific index

2. ArrayList
2.1 ArrayList and Object-Oriented Design

	•	The ArrayList is a generic class that works with objects, not primitive types.
	•	Java provides wrapper classes (e.g., Integer for int, Boolean for boolean) that convert primitive types into objects. This process is called autoboxing.
	-> Why Not Primitive Types?
	•	Type Safety: Collections need a unified way to handle various types using the Object class as a base. Primitive types do not inherit from Object.
	•	Polymorphism: Primitive types do not support polymorphism or method overriding. Wrappers provide methods (e.g., toString(), compareTo()) for enhanced functionality.

	Summary:
	ArrayLists work like shelves designed to store labeled boxes (objects). Primitive types are like raw items that need to be packed into boxes (wrapper classes) before storing.”

	CheatSheet:
	1.   ArrayList<String> stringList = new ArrayList<String>();
	2.   ArrayList<String> capacityList = new ArrayList<>(50); // Initialize with an initial capacity of 50

		remove(int index): Remove the element at the specified position/

3. Linked Lists - Interview Notes (Expanded)

	1.	Definition:
	•	A data structure where elements (nodes) are linked in a sequence. Each node contains:
	•	Data: The value stored (e.g., a city’s name).
	•	Next: A reference/pointer to the next node.

	2.	Memory Allocation:
	•	Non-continuous; nodes are allocated anywhere in memory.
	•	Each node connects to the next, forming a sequence.
	•	Last node’s pointer is null (end of the list).

	3.	Key Features of Singly Linked Lists:
	•	One-Way Flow: Nodes link only to the next node.
	•	Head Node: Starting point of the list.
	•	Dynamic memory allocation—memory is assigned only when a node is added.

	4.	Advantages Over Arrays:
	•	Flexible Size: No need to predefine size.
	•	Efficient Updates: Easy to add/remove nodes without rearranging.

	5.	Manipulation Examples:
	•	Add Node: Update the next reference of the preceding node to include the new node.
	•	Example: Add Philadelphia between Richmond and Washington by adjusting links.
	•	Remove Node: Skip the node by updating the preceding node’s reference to point to the next node.
	•	Example: Remove Philadelphia by connecting New York directly to Richmond.
	•	Update Node Data: Modify the data in a node without changing the structure.

	6.	Real-World Analogies:
	•	Train journey: Each city (node) is connected in sequence. Adding/removing stops is like modifying a linked list.
	•	Playlist or to-do list: Manage dynamic sequences of data.

	7.	Key Concepts in Java:
	•	Node Class: Defines individual nodes with data and a next reference.
	•	LinkedList Class: Manages the head node and operations like add, remove, or update.
	•	Head Node Initialization: Initially set to null for an empty list.

	8.	Use Cases:
	•	Ideal for dynamic data where elements are frequently added or removed.
	•	Efficient for queues, playlists, or dynamic task management.
	
	9.	Key Takeaway:
	•	Linked lists are simple yet powerful structures for managing dynamic data sequences efficiently. Singly linked lists are best for one-directional processing, while doubly linked lists allow two-way traversal.
