1. Array:
	•   Memory Inefficiency: Middle insertions or deletions often require shifting elements, leading to memory overhead.
	•	Memory Waste while deletion : Replacing elements with null does not reduce the array size, causing potential memory inefficiency.
	•	Null Pointer Exceptions: Improper handling of null values may lead to runtime errors if we make the values as null.
	•	Fixed Size Limitation: Arrays have a fixed size, making dynamic insertions/deletions challenging compared to data structures like linked lists.
	•	Performance Impact: Frequent insertions/deletions in the middle of large arrays may significantly impact performance due to shifting elements.
    •   Initializing an array static means allocating memory and setting initial values for each element optionally.
    • It is generally recommended to put square brackets before the variable name for clarity and consistency while defining array
    • Arrays.fill() method is used to fill the arrays dynamically or fill at specific index
	> Arrays are useful for static usage of data such as movie seats ,use boolean instead of int (int takes 4 bytes , boolean takes 1 )

2. ArrayList
2.1 ArrayList and Object-Oriented Design

	•	The ArrayList is a generic class that works with objects, not primitive types.
	•	Java provides wrapper classes (e.g., Integer for int, Boolean for boolean) that convert primitive types into objects. This process is called autoboxing.
	-> Why Not Primitive Types?
	•	Type Safety: Collections need a unified way to handle various types using the Object class as a base. Primitive types do not inherit from Object.
	•	Polymorphism: Primitive types do not support polymorphism or method overriding. Wrappers provide methods (e.g., toString(), compareTo()) for enhanced functionality.

	Summary:
	ArrayLists work like shelves designed to store labeled boxes (objects). Primitive types are like raw items that need to be packed into boxes (wrapper classes) before storing.”
