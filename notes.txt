2. ArrayList
2.1 ArrayList and Object-Oriented Design

	•	The ArrayList is a generic class that works with objects, not primitive types.
	•	Java provides wrapper classes (e.g., Integer for int, Boolean for boolean) that convert primitive types into objects. This process is called autoboxing.
	-> Why Not Primitive Types?
	•	Type Safety: Collections need a unified way to handle various types using the Object class as a base. Primitive types do not inherit from Object.
	•	Polymorphism: Primitive types do not support polymorphism or method overriding. Wrappers provide methods (e.g., toString(), compareTo()) for enhanced functionality.

	Summary:
	ArrayLists work like shelves designed to store labeled boxes (objects). Primitive types are like raw items that need to be packed into boxes (wrapper classes) before storing.”

Linked Lists 

Definition:

	•	Linked List: A sequence-based data structure where each element (node) consists of:
	•	Data: The value stored (e.g., a book title or city name).
	•	Next: A pointer/reference to the next node in the sequence.

Types of Linked Lists:

	1.	Singly Linked List:
	•	Nodes are connected in one direction, linking only to the next node.
	2.	Doubly Linked List:
	•	Nodes are connected in both directions, linking to the next and previous nodes.

Memory Allocation:

	•	Non-Continuous: Nodes are scattered in memory but are linked via pointers.
	•	Dynamic: Memory is allocated when a node is added.
	•	Node Composition:
	•	Singly Linked List: Data + Next pointer.
	•	Doubly Linked List: Data + Next pointer + Prev pointer.

Operations:

Insertions & Modifications:

	1.	Singly Linked List:
	•	Adding at the end: Attach a new node to the last node.
	•	Adding in the middle: Traverse to the insertion point, then update pointers.
	•	Example:

// Insert new node after a specified node
newNode.next = previousNode.next;
previousNode.next = newNode;


	2.	Doubly Linked List:
	•	Adding anywhere is easier since each node links both ways.
	•	Example:

// Insert new node after a specified node
newNode.next = previousNode.next;
newNode.prev = previousNode;
if (previousNode.next != null) {
    previousNode.next.prev = newNode;
}
previousNode.next = newNode;



Traversal:

	1.	Singly Linked List:
	•	One-directional, forward-only.
	•	Example:

current = current.next;


	2.	Doubly Linked List:
	•	Bi-directional, forward and backward traversal.
	•	Useful for revisiting or planning ahead.

Deletion:

	•	Singly Linked List: Skip the node by updating the previous node’s pointer.
	•	Doubly Linked List: Update both Prev and Next pointers of neighboring nodes.

Time Complexity:

Arrays:

	1.	Access:
	•	Time: O(1) (instant access using an index).
	•	Example:

int photo = photos[2]; // Access directly by index


	2.	Insertion:
	•	Time: O(n) (shifting elements to make space).
	•	Example:

// Insert in the middle
for (int i = size; i > index; i--) {
    photos[i] = photos[i - 1];
}
photos[index] = newPhoto;


	3.	Deletion:
	•	Time: O(n) (shifting elements to fill the gap).
	•	Example:

// Delete from the middle
for (int i = index; i < size - 1; i++) {
    photos[i] = photos[i + 1];
}



Linked Lists:

	1.	Access:
	•	Time: O(n) (traversal required to locate an element).
	•	Example:

Node current = head;
while (index-- > 0) {
    current = current.next;
}


	2.	Insertion:
	•	At Start/End: O(1) (update pointers).
	•	In Middle: O(n) (traversal to locate the position, then insertion).
	•	Example:

newNode.next = current.next;
current.next = newNode;


	3.	Deletion:
	•	At Start/End: O(1) (update pointers).
	•	In Middle: O(n) (traversal to locate the node, then deletion).
	•	Example:

current.next = current.next.next;

Memory Usage:

	•	Singly Linked List:
	•	Minimal memory: One pointer per node.
	•	Doubly Linked List:
	•	Extra memory: Additional pointer (Prev) per node.
	•	Suitable for complex data handling but can become memory-intensive in large-scale systems.

Advantages:

	1.	Singly Linked List:
	•	Memory-efficient.
	•	Suitable for sequential data processing.
	•	Easy to implement and manage for simple use cases.
	2.	Doubly Linked List:
	•	Flexibility for two-way traversal.
	•	Efficient for frequent additions or deletions in both directions.
	•	Ideal for scenarios like navigation systems or where dynamic data changes are common.

Key Concepts:

	•	Node Class: Defines a node with data and pointer(s).
	•	LinkedList Class: Manages operations like add, remove, and traverse.
	•	Head Node: Starting point of the list; initialized as null for an empty list.

Use Cases:

	•	Singly Linked List:
	•	Suitable for queues, playlists, or dynamic task management.
	•	Doubly Linked List:
	•	Used in navigation systems, undo-redo functionality, or applications requiring frequent backtracking.

Key Takeaway:

	•	Arrays: Offer quick access (O(1)), but are less flexible for insertions and deletions (O(n) for middle operations).
	•	Singly Linked Lists: Memory-efficient, ideal for sequential tasks.
	•	Doubly Linked Lists: Provide flexibility for complex scenarios, suitable for frequent updates and two-way traversal.

Choosing between them depends on the application needs and trade-offs between memory usage and time complexity.

Stacks : 
Interview Notes on Stacks

	1.	What is a Stack?
	•	A linear data structure following the Last In, First Out (LIFO) principle.
	•	Example: Stack of plates – the last plate added is the first one removed.
	2.	Operations:
	•	Push: Add an element to the top of the stack.
	•	Pop: Remove the top element of the stack.
	•	Peek: View the top element without removing it.
	3.	Applications of Stacks:
	•	Undo Mechanisms:
	•	Actions are recorded on the stack.
	•	Undo removes the top action (reverses the last action).
	•	Function Calls:
	•	Tracks return addresses and local variables for nested calls.
	•	Example: Recursive function calls use stacks to manage execution.
	•	Expression Conversion (Infix to Postfix):
	•	Infix (e.g., 3 + 4 * 5) → Postfix (3 4 5 * +).
	•	Operators are pushed and popped to ensure correct precedence.
	4.	Example - Undo Mechanism:
	•	Actions (e.g., typing): Pushed onto the stack.
	•	Undo: Pops the last action and reverses it.
	•	Ideal for step-by-step backtracking.
	5.	Example - Function Call Stack:
	•	Recursive example:
	•	Function call stack grows with each recursive call (e.g., add(3,2) → add(4,1) → add(5,0)).
	•	Base case reached: Stack unwinds (removes elements in reverse order).
	6.	Example - Expression Conversion:
	•	Convert 3 + 4 * 5 to postfix:
	•	Push operators based on precedence.
	•	Postfix expression: 3 4 5 * +.
	•	Ensures computation order without ambiguity.
	7.	Real-Life Analogies:
	•	Navigating web pages (Back and Forward buttons).
	•	Undoing steps in a text editor.
	8.	Key Benefits:
	•	Simplifies managing tasks in reverse order.
	•	Ensures organized and error-free execution flow.
	•	Efficiently handles nested or sequential tasks.

Key Takeaway: Stacks are simple but powerful tools essential for managing ordered tasks, undo mechanisms, function calls, and more in computer science.

Queues:
Notes on Queues

	•	Definition: A queue is a linear data structure following the First In, First Out (FIFO) principle, where the first element added is the first to be removed.
	•	Real-life analogy: Like a line at a coffee shop, the first person in line is served first.
	•	Applications in Computing:
	•	Operating Systems:
	•	Used for CPU scheduling (e.g., First Come First Serve or FCFS scheduling).
	•	Manages tasks like I/O requests and printer spooling, ensuring fairness and order.
	•	Networking:
	•	Handles data packets, ensuring they are processed in the correct order to avoid congestion and ensure reliability.
	•	Prioritizes critical packets (e.g., video calls over file downloads).
	•	Devices:
	•	Keyboards, mice, and printers queue requests to the CPU for sequential processing.
	•	Examples:
	•	CPU Task Scheduling: Tasks are queued and processed in arrival order.
	•	Printer Spooling: Print jobs are organized in a queue to avoid chaos.
	•	Network Routing: Routers use queues to process packets efficiently.
	•	Importance: Queues ensure fairness, organization, and efficiency in managing tasks across systems and networks, preventing chaos and ensuring smooth operations.
